# Как использовать плагины sdlc / django-plugin / python-foundation

- **Дата:** 2026-10-16
- **Проект:** `task-manager-060326`
- **Установленные плагины:** `sdlc`, `django-plugin`, `python-foundation` версии 2.0.0 (из `sdlc-marketplace`), с локально исправленными хуками — см. [PR #32](https://github.com/AratKruglik/claude-sdlc/pull/32)

Использовать плагины можно тремя способами: часть работает сама, скиллы подключает Claude по вашей просьбе, а конвейер `/sdlc:start` запускаете вы.

## 1. Работает само, ничего делать не нужно

Это хуки `django-plugin`, они включаются при каждой правке файла.

- **Форматирование ruff:** любой `.py`, который Claude создаёт или правит, автоматически форматируется целиком.
- **Защита конфигов и проверка `ruff check .`:** работают только во время запуска `/sdlc:start`, в остальное время ничего не блокируют.

## 2. Скиллы: просите словами

У всех шести скиллов стоит `user-invocable: false`, поэтому команды вида `/django-plugin:...` нет. Достаточно написать в сообщении.

| Скилл | Когда пригодится | Пример просьбы |
|---|---|---|
| `django-plugin:django-orm-patterns` | Запросы, `annotate`/`aggregate`, N+1, `select_related`, `F`/`Q`, транзакции | «Проверь orm1.py по django-orm-patterns» |
| `django-plugin:django-conventions` | Views, сериализаторы DRF, `urls.py`, права доступа, админка | «Напиши view для тегов по django-conventions» |
| `python-foundation:pytest-testing` | Тесты | «Напиши тесты к get_all_projects по pytest-testing» |
| `python-foundation:python-conventions` | Стиль, типизация, enum | «Проверь стиль views.py» |
| `python-foundation:python-tooling` | ruff, mypy, зависимости, `requirements.txt` | «Настрой ruff для проекта» |

Это самый полезный вариант для учёбы: код вы пишете сами, а проверку и подсказки Claude даёт по правилам скилла.

## 3. Конвейер `/sdlc:start`: целая фича под ключ

```
/sdlc:start "Сериализатор и CRUD-эндпоинты для тегов (задания 14–19)"
```

Конвейер сам проходит все этапы:

1. Анализ требований (`business-analyst`).
2. Код (`django-architect`).
3. Миграции (`django-migrations-specialist`).
4. Тесты и проверка безопасности (идут параллельно).
5. Документация и PR.

Сценарий выбирается флагом `--workflow`:

- `bugfix` или `refactor` — без этапа анализа;
- `docs-only` — только документация;
- `--resume` — продолжить прерванный запуск.

**Когда подходит:** реальная фича на несколько файлов, где нужны и код, и тесты, и миграции.

**Когда не подходит:**

- Учебные задания. Код пишут агенты, а не вы, поэтому навык не тренируется.
- Мелкие правки. Конвейер запускает 5–6 агентов, причём анализ требований и проверка безопасности идут на opus, так что это заметно дороже обычной просьбы.

**Перед запуском в этом репозитории:**

- Сохраните незакоммиченные изменения. Конвейер создаст новую ветку от `main` и в конце откроет PR через `gh`.
- Установите `jq` (`scoop install jq`). Без него не будет отчёта о стоимости запуска.
- Дополнительные плагины (superpowers, grill-me) не установлены. Конвейер работает и без них, только с предупреждениями и менее строгими проверками.

## 4. Служебные команды

| Команда | Что делает |
|---|---|
| `/sdlc:doctor` | Проверка окружения: зависимости, стек, хуки, git flow |
| `/sdlc:list-stacks` | Какой стек определён для проекта (здесь — django) |
| `/sdlc:security-init` | Записывает в проект правила безопасности для Django. Создаёт файлы, есть `--dry-run` для предпросмотра |
| `/sdlc:batch "Задача 1" "Задача 2"` | Несколько конвейеров параллельно в отдельных worktree. Самый дорогой вариант |

## Коротко: что выбрать

| Ситуация | Что использовать |
|---|---|
| Сделали домашнее задание, хотите проверку | Попросить Claude проверить с нужным скиллом |
| Не понимаете, как написать запрос или view | Попросить объяснить или показать пример по скиллу |
| Нужна готовая фича с тестами и PR | `/sdlc:start "..."` |
| Что-то сломалось в плагинах | `/sdlc:doctor` |
