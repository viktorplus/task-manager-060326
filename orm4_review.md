## Замечания по заданиям

### Задание 1 — проекты за текущий месяц ✅

- Фильтр по месяцу **и** году (`created_at__month` + `created_at__year`) — лучше эталона из PDF, где проверяется только месяц, без года.
- Явной проверки «если есть хоть один проект» нет: при пустом результате цикл просто ничего не выведет. Формально это допустимо.

Фактический вывод: 5 проектов (`Project1` … `Project5`), все созданы 06–08.10.2026.

### Задание 2 — файлы за день недели ✅

- `ExtractWeekDay`, аннотация `weekday`, фильтр по ней и сообщение `Empty Data` — всё на месте.
- Переменная называется `monday_project_files`, а фильтр стоит `weekday=3`, то есть **вторник**. В комментарии это объяснено, но имя переменной вводит в заблуждение.
- `print(project_file.file)` выводит путь относительно `MEDIA_ROOT` (`projects/readme.txt`), а не полный путь на диске. Если имелся в виду полный путь, нужен `.file.path`.
- `import django` внутри фрагмента лишний.

Фактический вывод: `Название файла: 1`, `Путь к файлу: projects/readme.txt`.

### Задание 3 — общее количество проектов ✅

`Project.objects.count()` — соответствует условию. Вывод: `Количество всех проектов: 5`.

### Задание 4 — количество файлов для каждого проекта ✅

- Результат верный: `Project3`, `Project2` и `Project1` — по 1 файлу, `Project5` и `Project4` — по 0.
- Отдельный запрос `aggregate` на каждый проект (проблема N+1). Тот же результат даёт один запрос: `Project.objects.annotate(num_files=Count("files"))`. Подход повторяет эталон из PDF, поэтому это замечание по качеству, а не ошибка.
- Словарь строится по ключу `project.title`, а `title` не уникален: в модели уникальна только пара `title + description`. Два проекта с одинаковым названием в выводе сольются в одну строку.

### Задание 5 — среднее количество задач ⚠️

- По условию для каждого проекта нужно «среднее количество задач». Фактически выводится **количество** задач по каждому проекту и одно **общее** среднее по всем проектам: `Average Number of Tasks: 1.2`.
- Эта трактовка осмысленнее эталона: в PDF берётся `Avg('tasks__id')`, то есть среднее по идентификаторам задач. Но отличие от формулировки условия стоит пояснить комментарием в коде.
- `Count` внутри фрагмента не импортирован (импортируются только `Avg` и `Project`). Код работает только за счёт импорта в начале файла.

### Задание 6 — количество задач каждого пользователя ✅

`annotate(count_of_tasks=Count("tasks")).values("username", "count_of_tasks")` — соответствует условию, в том числе требованию ограничить поля. Вывод верный: например, `Backend` — 2 задачи, `DevOPS` — 1.

### Задание 7 — сортировка по приоритету и дате ⚠️

- `priority` в модели — строка (`TextChoices`: `low` / `medium` / `high`), поэтому `order_by("priority")` сортирует **по алфавиту**.
- Фактический порядок: `high, high, low, medium, medium, medium` — `low` оказывается раньше `medium`. По важности задачи так не упорядочены.
- `.all()` перед `.order_by()` лишний.

### Задание 8 — пользователи по загрузке ✅

`annotate` + `values("username", "count_of_tasks")` + `order_by("-count_of_tasks")` — соответствует условию, вывод отсортирован по убыванию. При равном числе задач порядок пользователей не определён, его можно закрепить второй сортировкой (например, по `username`).

### Задание 9 — пагинация задач ❌

- Закомментированный код под заголовком задания 9 — это **копия задания 8** (сортировка пользователей через `values_list`). К пагинации он отношения не имеет.
- Решение с `Paginator` лежит внутри `"""..."""`. Это строковый литерал, он **никогда не выполняется**. Импорт `Paginator` (пункт 2 условия) тоже находится только внутри этой строки.
- Если всё же выполнить код из строки, он работает: выводятся 6 задач с названием, статусом, приоритетом и пользователем. Но:
  - печатается `task.assignee`, то есть объект пользователя (через `__str__`), а не явно `task.assignee.username`;
  - для задачи без исполнителя выводится `Username: None` (задача «Frontend Task 2»);
  - имя `task` используется и для QuerySet, и для переменной цикла;
  - на каждую задачу идёт отдельный запрос за пользователем; это решает `select_related("assignee")`.
- В базе всего 6 задач, поэтому ограничение «ровно 10 на странице» на этих данных не проверить.

### Задание 10 — первый сериализатор ⚠️

- Кода в `orm4.py` нет, и это нормально: сериализатор находится в `core/serializers/projects.py` (`AllProjectsSerializer`).
- Используется поле `title` вместо `name` из условия — это правильно, потому что в вашей модели `Project` поле называется `title`.
- `rest_framework` есть в `INSTALLED_APPS`, DRF 3.18.3 установлен в `.venv`.
- **Пункт 2 не выполнен:** в `requirements.txt` нет `djangorestframework`.
- `requirements.txt` сохранён в кодировке UTF-16 (видимо, через `pip freeze >` в PowerShell). Его не читают `grep` и некоторые другие инструменты, лучше сохранить в UTF-8.

## Общие замечания по файлу

- Запуск `python orm4.py` ничего не выводит (код возврата 0): всё решение закомментировано или лежит в строке. Если проверяющий запустит файл, он не увидит ни одного результата.
